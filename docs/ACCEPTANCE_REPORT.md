## How this report was made

- **Master specification (§1).** Every row comes from the master-spec conformance audit of the
  committed tree at `6050e91` (2026-10-26): 255 requirements, each checked by an auditor and either
  confirmed by a skeptic pass or re-checked by the synthesizer at HEAD. Its evidence column is kept
  as recorded there (file:line references are to that tree). The artwork commit `6a07349` that
  followed changed none of the audited verdicts except where noted. During this wave the data
  workstream rebuilt the dataset with source licences in the manifest (G-07): the working tree now
  ships `50fefb5e828b` with the same counts as the audited `62e807e6d444`, which the audit evidence
  below still cites.
- **This wave's CI and documentation work** closed 27 rows (G-01–G-05, G-09–G-12, G-14, G-16 docs,
  G-33). Those rows say "closed this wave" and give the new evidence, which was verified in this
  wave (see IMPLEMENTATION_STATUS §1.11).
- **The other workstreams' rows** (G-07, G-08, G-13, G-15, G-17–G-22, G-24, G-25, G-28, G-29) were
  refreshed after the wave's final gate (2026-10-29, a fresh clone of the combined tree
  `82b840b9bc48`, IMPLEMENTATION_STATUS §2.1): each new verdict cites the test that guards it, and
  every one of those tests passed in that gate. Rows that are only partly closed stay PARTIAL and say
  what remains.
- **Not checkable here:** the audit's own gap list (`MASTER_SPEC_CONFORMANCE.md`) was no longer
  available at the gate, so this report's rows are the record of the G-items. G-06 is not referenced
  by any row and could not be checked.
- **Owner specifications (§2)** come from the QA acceptance checklist of 2026-10-24 (57 items, run
  on the real app with the real-handler backend, updated with the fix wave) and the artwork
  integration gates of 2026-10-26 ([LPU_ISOMETRIC_ASSET_INTEGRATION.md](LPU_ISOMETRIC_ASSET_INTEGRATION.md)).

**Verdicts.** **PASS**: met, with evidence. **PARTIAL**: part of the requirement is met; the open
item says what is missing. **FAIL**: not met. **NOT TESTABLE**: cannot be verified by automation or
in this environment (a real phone, a person with a screen reader, real imagery). **SUPERSEDED**: an
owner decision replaced the requirement. **N/A**: does not apply (no legitimate source, or the spec
text is truncated).
