# Campus data

Everything the app shows comes from files in this directory, turned into
`public/data/*` by a deterministic, offline build. Nothing is invented: an
unnamed OpenStreetMap building stays "Unnamed building", missing hours stay
unknown, and an unmapped facility is an honest empty state.

## Layout

| Path                | What it holds                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `raw/osm/`          | Committed OpenStreetMap snapshot (`campus-bbox.osm`, `boundary-relation-21599790.osm`) and `SOURCE.json` (source URL, licence, retrieval time, method, bbox). Never edited by hand.                                                                                                                                                                                                                             |
| `raw/detections/`   | Committed, small detection snapshots filtered to the map extent: `microsoft-ml/` (footprints exactly as published, `SOURCE.json`, CDLA-Permissive-2.0 text) and `google-open-buildings/` (points, `SOURCE.json`, ODbL notice). Written by `npm run data:fetch-footprints`; offline builds use them.                                                                                                             |
| `curated/`          | Hand-curated, **sourced** records: `aliases.json`, `overrides.json`, `organizations.json` (`scripts/lib/curated-schema.ts`); `boundary-review.json` (uncertain boundary sections + dated membership decisions); `landmarks.json` (ids that must never disappear); `directory-keys.json` (map-key lock, written only by `npm run data:keys`); `count-change-acceptance.json` (acknowledged large count changes). |
| `schemas/`          | JSON Schema copies of the curated formats, regenerated by every default build (for editors and reviewers).                                                                                                                                                                                                                                                                                                      |
| `live/`             | Reserved for live/status feeds. No public live source exists for LPU today, so the app shows such features as unavailable.                                                                                                                                                                                                                                                                                      |
| `.cache/` (ignored) | `previous-manifest.json`, the manifest replaced by the last build; a count-change baseline only when it is a valid current-schema manifest (the committed manifest at git HEAD comes first).                                                                                                                                                                                                                    |

Generated output (schema v2, docs/MODULE_CONTRACTS.md "v2 geographic contract"): `public/data/`
(`manifest.json`, `boundary.geojson`, `buildings.geojson` — campus inventory only, `basemap.geojson`,
`places.json` — campus places only, `relations.json`, `graph.json` — edges tagged `campus`,
`quality-report.json`, and the lazily loaded `context-places.json` — off-campus points for the opt-in
"Nearby, outside campus" layer, `detections.geojson` — unverified machine detections, `boundary-review.json`,
`licenses/`), `docs/DATA_QUALITY_REPORT.md` and `docs/CAMPUS_BUILDING_COVERAGE.md` (both generated).

## Commands

```sh
npm run data:build      # raw + curated → public/data (offline, byte-identical across rebuilds)
npm run data:validate   # schemas + invariants; exit 1 on any error, warnings are printed with counts
npm run data:check      # both of the above
npm run data:fetch      # refresh the raw snapshot (network); no-op if it exists
npm run data:fetch -- --force
npm run data:fetch-footprints   # refresh the detection snapshots (network; Microsoft tile + Google points)
npm run data:keys               # assign map keys for new eligible buildings into curated/directory-keys.json
npm run data:keys -- --check    # exit 1 if the lock is out of date (never renumbers)
node scripts/validate-data.ts --check-links      # also HEAD-request every website (network, opt-in)
node scripts/build-data.ts --input <rawDir> --curated <dir> --out <dir> [--relation <id>]
```

Set `DATA_FETCH_CONTACT` (an e-mail address or URL) before fetching; it is
sent in the `User-Agent` as the OSM/Overpass usage policies ask. The fetcher
tries Overpass (two public endpoints, 3 retries with exponential backoff), then
falls back to the OSM API 0.6 (`/relation/21599790/full` and `/map?bbox=`).
Overpass was unreachable from the machine that took the committed snapshot, so
`SOURCE.json` records `"method": "osm-api-map"`. The fetch bbox is the campus
boundary extent plus ≈ 500 m, so the off-campus Law Gate area is included.

After a refresh: run `npm run data:check`, read the count-change warnings and
`docs/DATA_QUALITY_REPORT.md`, then commit the raw files and the generated
output together.

## Regression guards

`npm run data:build` writes to `public/data.staging`, validates there and only
then swaps into `public/data`; a build with any validation error leaves
`public/data` and the generated docs untouched. Errors include: a footprint
with campus status `outside`/`uncertain` in `buildings.geojson`, an off-campus
feature in `places.json`, a building place out of sync with its footprint, a
landmark from `curated/landmarks.json` missing, and a count change above 40 %.

**Count-change guard.** Every manifest count is compared with the BASELINE:
the manifest committed at git HEAD (any schema version), else a valid
current-schema `.cache/previous-manifest.json`, else the manifest being
replaced. A change above 15 % warns; above 40 % fails, unless it moves fewer
than 5 records. An intentional large change is acknowledged, never hidden:

- durably in `curated/count-change-acceptance.json` — `{baselineDatasetVersion,
reason (≥ 20 characters), acceptedBy, acceptedAt}`, pinned to the baseline it
  accepts. It stops applying when the baseline changes and is then reported as
  stale (`count-acceptance-stale`): delete the entry after the change is committed;
- once, locally: `node scripts/build-data.ts --accept-count-changes "<reason>"`
  (same flag for `scripts/validate-data.ts`).

Accepted changes stay visible as warnings and are written, with the reason, to
both generated reports. A missing landmark is never accepted. The entry for
the v1 → v2 campus-only migration is pinned to the v1 dataset `b628c5855b1d`.

**Landmarks.** `curated/landmarks.json` lists `{id, in, why}` for named or
verified campus features (currently the boundary relation and every named
campus building). Add one only for a feature in the current build, with what
makes it a landmark; removing one on purpose means editing the file in the same
change.

**Boundary review.** `curated/boundary-review.json` holds open sections (geometry
copied from OSM nodes named in `evidence`) and per-footprint decisions
(`featureId, status, decidedAt, decidedBy, source {kind, ref}, note`). None is
pre-filled: only the owner, an official publication, a survey or an OSM
boundary fix resolves an item.

## How OSM becomes places, buildings and a graph

- **Boundary**: relation 21599790's outer ways are assembled into closed
  rings. If it is missing or does not close, the build fails; it never
  substitutes a rectangle.
- **Buildings**: closed `building=*` ways and building multipolygons (holes
  kept). Height: `height` tag (`osm-height`, a measurement) → else
  `building:levels × APP_CONFIG.map.metresPerLevel` (`osm-levels-estimate`) →
  else `APP_CONFIG.map.fallbackBuildingHeightM` (`fallback`, a placeholder).
  `min_height` / `building:min_level` lift the base; a base at or above the top
  is ignored and listed in the quality report. Invalid rings (open,
  self-intersecting, zero area) are skipped and listed.
- **Categories** come from `src/config/categories.ts` matchers with this
  priority: (1) use tags — any matcher whose key is not `building` (amenity,
  shop, tourism, leisure, …) in registry order; (2) building-type values
  (`building=dormitory` → hostel, …); (3) the generic `building` category. So
  a `building=yes` + `amenity=restaurant` footprint is _food_, not _building_.
- **Gates**: `barrier=gate|lift_gate|…` and `man_made=ceremonial_gate` become
  `kind: 'gate'` with a description of what is actually mapped. Features that
  are merely _named_ "… gate" (e.g. the residential area "Law gate",
  `way/752027029`) stay areas/landmarks and say they are not a campus entrance.
  `entrance=*` nodes become entrances; one on a building outline gets an
  `accessed_via` relation, others are listed as unattached.
- **Walking/cycling graph**: one edge per consecutive OSM node pair; ways
  connect only through shared nodes. Walking is allowed on footway, path,
  pedestrian, steps, living_street, residential, service, unclassified,
  tertiary, secondary, track, corridor, crossing and cycleway (unless
  `foot=no`). Trunk, primary and motorway are excluded unless
  `foot=yes|designated` (conservative: fast traffic, usually no sidewalk).
  Cycling: `ride` on roads/cycleway/track/path, `push` on
  footway/pedestrian/steps/corridor unless `bicycle=yes|designated`, `no` for
  `bicycle=no` or where walking is banned; trunk/primary only with an explicit
  `bicycle=yes|designated`. `access=private|no` excludes a mode unless that
  mode is explicitly allowed. Vehicle `oneway` applies to bicycles unless
  `oneway:bicycle=no`; `onewayFoot` only from `oneway:foot=yes`. Steps are
  `wheelchair: 'no'` unless tagged; everything else untagged is `unknown`.
  Disconnected components are reported, **never** bridged.
- **Connectors**: each located place gets the nearest walkable graph node
  within `APP_CONFIG.routing.maxPlaceConnectorM` (buildings measured from
  their outline). Farther places stay unroutable and are listed in the report.
- **Relations**: `located_in` (point inside a footprint), `accessed_via`,
  `part_of` (on-campus place → campus area) and `nearby` (≤ 3 essential
  facilities within 150 m, straight-line only — never implies a path).

## Curated records — rules

1. **Cite a source** for every record (`source.name`, `source.url`,
   `source.retrievedAt`). No source, no record.
2. **Never invent coordinates.** A curated record gets a position only through
   `anchor.target`, which must be an existing OSM place id in the snapshot
   (`osm:way/123`); an unresolved anchor fails the build.
3. **No guessed names.** Do not add block numbers or nicknames from memory;
   add an alias only when a cited source ties that name to that exact feature.
4. **Overrides state how they were checked**: `check` is `physical-survey`,
   `official-publication` or `unverified-report`. Only the first two mark a
   record `verified` and set `lastVerifiedAt`; an `unverified-report` is applied as
   `unverified` and its date is kept only in the provenance notes.
5. Organizations without a published position stay unlocated
   (`location: null`): searchable, never drawn or routed.

```jsonc
// aliases.json
{ "aliases": [{ "target": "osm:way/123", "aliases": ["…"],
    "source": { "name": "…", "url": "https://…", "retrievedAt": "2026-10-23" } }] }
// overrides.json
{ "overrides": [{ "target": "osm:way/123", "set": { "openingHours": "Mo-Fr 09:00-17:00" },
    "source": { "name": "…", "url": "https://…" }, "check": "physical-survey",
    "lastVerifiedAt": "2026-10-23", "verifiedBy": "…" }] }
```
